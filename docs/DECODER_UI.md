# Crash Telemetry Decoder

`Crash_Decoder` is a WPF desktop viewer for `crash_telemetry_dump.json` files generated by the recorder. It uses a Windows 11–style shell, rounded cards, and a debugger navigation rail.

## Open a dump

```powershell
dotnet run --project src/Crash_Decoder -- C:\path\to\crash_telemetry_dump.json
```

Or launch it with no argument and select a file. The viewer rejects unrecognized schemas, empty dumps, absent fields, and non-finite control values rather than guessing at data.

## Pages and controls

- **Dashboard** — SimConnect state, logging state, selected profile, timeline area, and quick actions.
- **Live recording** — local preferences for recording enablement, dump retention, history length, and sample rate. The SDK-enabled recorder reads them at startup; restart it after changes. They do not reconfigure the simulator.
- **Aircraft profiles** — a local profile name and optional user-entered aircraft title. The SDK-enabled recorder contains a separate title/airspeed/altitude request, but it still requires target-SDK and simulator validation. The entered title is labeled as user-entered when used as a fallback.
- **Telemetry tables** — a classic debugger-style table navigator in the upper-left, with raw input frames on the right.
- **Settings** — persistent MSFS 2020/2024 Community-folder choices and detected candidates.

The navigation rail and the telemetry-table rail both have draggable splitters, and the main window has ordinary Windows move/resize controls.

## Tray controls

Minimize the main window with either its title-bar control or the dashboard control to keep the viewer running in the Windows notification area. Click the Blackbox tray icon for a compact live dashboard with connection state, latest input values, rolling-buffer use, and aircraft information. It offers **Mark event + export**, **Open full screen**, **Minimize to tray**, and **Exit Blackbox**. Double-click the tray icon to restore the maximized dashboard. Closing the main window exits the viewer and removes its tray icon. Tray mode does not start the external recorder on its own.

The event button is enabled only while a fresh recorder heartbeat includes actual input frames. It creates a timestamped developer ZIP in the configured export folder. If no folder is configured, the first mark opens a folder chooser. The panel reports whether the recorder confirmed the export. See [event capture](EVENT_CAPTURE.md) for ZIP contents and limits.

The executable icon is generated during build from the app's blue tile and white four-point mark. Controls on the navigation rail, recording page, settings page, toolbar, and tray panel have short tooltips.

## Developer handoff and snapshots

With a dump open, the tool can create three local artifacts at a location chosen by the user:

- **Snapshot** writes the selected frame (or the final frame if none is selected) to a small JSON file.
- **Export last 10s** writes the last ten seconds of the loaded dump to a ZIP.
- **Export developer bundle** writes the entire loaded dump to a ZIP.

Bundles contain `telemetry.json`, a machine-readable `manifest.json`, and a short README. They intentionally exclude local Community-folder paths, settings, simulator binaries, and unrelated files. Review the selected telemetry before sharing it.

## Rolling capacity

The retention selector now supports up to one hour. The dashboard estimates its planned frame capacity from retention × sample rate. During a real monitor session, the live status contract can supply the actual count/capacity; the UI warns at 90%, and the recorder ring buffer raises a one-time 90% capacity event. At full capacity it remains a rolling buffer, overwriting the oldest frames rather than stopping capture.

The viewer reads saved dumps and the external recorder's local live status. The external recorder owns the telemetry buffer and event exports. Neither component infers a root cause or claims that a control movement caused a simulator crash.

## Windows 11 presentation

The WPF shell requests the Windows 11 dark title bar and rounded-window preference from DWM when the operating system supports it. The app still runs with its ordinary WPF fallback on older Windows versions.

## Theme and readability

Settings includes an **Appearance** selector with **System**, **Light**, and **Dark** modes. System mode reads the current Windows app-theme preference each time the decoder launches; Light and Dark are explicit local overrides. The app uses custom theme-aware checkbox and dropdown templates so recording controls remain readable instead of falling back to the bright default WPF control theme.

## Options and status

The **Settings** page provides simulator-folder options:

- It reads the `InstalledPackagesPath` entry from the standard MSFS 2020 and MSFS 2024 `UserCfg.opt` locations, then lists the `Community` and (for 2024) `Community2024` candidates it finds.
- It also lists the standard Steam and Microsoft Store fallback locations. The list is advisory: no folders are created, moved, or modified.
- Double-click a candidate to save it as the explicit MSFS 2020 or MSFS 2024 Community location. You can instead choose a folder manually. The choices are stored only in `%LocalAppData%\MSFS-Input-Blackbox\settings.json`.
- The toolbar reads a local recorder-status file every two seconds. When the live SimConnect monitor opens, receives frames, disconnects, or stops, it updates that file; until then it correctly says **Recorder not running**, rather than guessing that MSFS is connected.

Microsoft documents that `UserCfg.opt` identifies the active installed-packages path, and MSFS 2024 distinguishes `Community` from `Community2024`; use the in-sim Virtual File System tool when an installation uses a custom location.
